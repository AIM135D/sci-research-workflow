# 多代理使用指南

多代理适合多个边界清楚、可以独立开展的工作，例如在同一组已授权材料上，一方核对论文元数据，另一方检查实验设计。对于一段润色或单篇论文查询，主 Agent 通常可以直接完成。

## 启动条件

默认单 Agent。用户需要明确提出启动多代理，并选择或授权选择每个所需角色的模型；主会话的模型由客户端控制。启动前确认当前客户端支持相应角色、显式模型选择、权限和可用并发。模型不可用时报告，不能悄悄替换；也不必为了凑齐六个角色而启动无任务的代理。

仓库的六份角色定义位于 `.codex/agents/`，不指定模型或推理强度。配置只设置允许的并发上限，不代表已启动代理或可获得同等数量的并发资源。具体配置格式和继承行为见 [Codex Subagents](https://developers.openai.com/codex/multi-agent)。

## 分派一项任务

主 Agent 为每项任务写明：任务目标、输入及来源、允许和禁止的操作、可写文件、模型、预算、交付物、验收条件和停止条件。保密稿件或未公开想法只能在用户授权和适用政策允许的范围内处理。子代理不能自行改变研究目标、再委派、批准实验或替研究者作最终决定。

独立阅读任务可以并行。创新判断依赖文献，实验计划依赖明确假设，实验执行依赖授权和资源检查；依赖未满足时应等待，不用猜测填补。默认进行一次主要审查；只有未解决的重大问题或用户明确要求，才增加有明确职责的专项审查。

## 接收结果

每个角色应报告实际完成的工作、使用的证据或文件、检查结果、未知项、产生的副作用以及需要主 Agent 决定的事项。不同意见要回到原论文、原始数据或代码核对，不能以代理数量投票决定科学问题。

一个共享产物同时只有一个写入者。多个任务使用同一 GPU 时，需要真实互斥锁或经过确认的不重叠窗口。角色文件中的“只读”是行为指令，不等于文件系统权限或安全隔离。
