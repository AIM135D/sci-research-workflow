# 工作流与决策指南

研究过程通常会往返于问题、证据和实验之间。下面列出每一步需要哪些材料、产生什么结果，以及证据不足时如何停止。它是可选的导航，并不要求每个请求都执行全部阶段。

## 1. 确定问题

写清研究对象、实际约束、希望改善的指标、可用数据和资源。区分作者已经观察到的事实与想验证的假设。如果问题只说“提高性能”，需要先知道任务、比较对象和评价方式，否则无法判断什么变化有意义。

**交付：** 一段问题陈述，以及已知条件和未知项。**停在这里：** 用户只要求讨论问题，或必要的任务范围尚不清楚。

## 2. 检索与核验

使用 `sci-literature-search` 拆解任务、机制、应用场景和同义词；选择相关的数据库与原始来源。记录查询时间、范围、版本、阅读层级和缺失资料。论文索引可以帮助发现候选工作，但核验标题或 DOI 不能证明某句话得到论文支持；涉及方法差异时需要查看相关方法正文及条件。

**交付：** 可回溯的文献与主张记录。**停在这里：** 用户只要求文献清单；全文不可访问时标注“仅摘要”或“未核验”，不要据此肯定或否定创新性。

## 3. 查新与机制设计

使用 `sci-innovation-selection` 或 `sci-novelty-check`，把候选方法与最近邻按输入、关键机制、训练方式、应用条件和评价方式对齐。新数据集、新术语或模块拼接本身不自动构成机制创新。一个有价值的候选应能说明：现有方法的哪个具体限制与目标有关、拟议机制为什么可能改变该限制、什么观察会推翻它。

| 判断 | 使用条件 |
| --- | --- |
| PROCEED | 当前证据支持具有具体差异，且没有已知致命问题；仍需后续验证 |
| REVISE | 已发现可明确修正的重合或机制问题 |
| REJECT | 有具体证据表明核心方案重合，或存在明确的致命问题 |
| INSUFFICIENT EVIDENCE | 关键论文、方法细节或其他必要证据不可得 |

这些标签是工作记录，不是录用概率。若检索范围有限，就同时保留查新日期、已查数据库和未覆盖范围。

## 4. 规划最小实验

用 `sci-experiment-plan` 将每个核心主张对应到一个能够区分它与替代解释的测试。列出数据与划分、可行的强基线、指标、条件、关键变量、随机性、硬件和时间预算。先定义成功、失败和无法判断三种结果，并列出早停条件。算力和耗时若未实测，应明确标为估算。

**交付：** 一份用户可审阅的实验计划。**授权边界：** 计划本身不授予训练、下载大模型、消耗 GPU 或修改远端数据的权限。

## 5. 执行与解释

只有在用户授权和资源检查之后才执行。保存实际的代码版本、环境、数据划分、命令、种子、日志、硬件、指标和失败记录。多人或多代理共享设备时，使用实际锁或明确的不重叠窗口；不要仅凭角色指令假设 GPU 独占。

解释时比较同条件下的基线、方差和代价，并考虑数据泄漏与其他可能解释。一个指标改善不自动证明机制成立；如果对照不能区分机制效果，应报告证据不足，再决定是否增加必要的消融。

## 6. 写作与审查

依据作者提供的真实结果，由 `sci-manuscript-writing` 在用户要求的语言和范围内写作或润色。写作前锁定关键事实，完成后核对数据、图表、引用和限制。默认先交付用户请求的中文论文内容；明确要求英文或翻译时直接按指定范围处理。

`sci-peer-review` 对稿件做只读检查。作者决定是否采纳建议；需要修改时仍由写作负责人处理。外部期刊的真实审稿、AI 使用和披露要求应查看该期刊的现行规定。

## 什么时候不需要完整流程

- 只要求改一个段落：直接做局部语言编辑，保留科学意义。
- 只要求查某篇论文：定位来源并说明阅读层级，不启动创新分析。
- 只要求审稿：报告基于已读材料的发现，不自动改稿或执行实验。
- 只要求实验计划：交付计划，不启动 GPU 任务。
